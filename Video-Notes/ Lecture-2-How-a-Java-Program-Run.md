Lecture 2: How a Java Program Runs ## Core Definitions Compiler: A translation layer that converts user-written Java code (.java) into Bytecode.

Bytecode: An intermediate code (.class format) generated by the compiler. It is not understandable by humans or machines directly, but it makes Java platform-independent.

**JVM** (Java Virtual Machine): A virtual machine/software that translates Bytecode into machine-understandable format and executes it on the computer.

## Java Execution Flow (Step-by-Step)

User writes code: Code is written in Java (saved as .java file).

Compilation: The Compiler translates the .java file.

Bytecode Generation: The compiler outputs a platform-independent Bytecode.

Interpretation/Execution: The **JVM** reads the Bytecode, converts it into machine-understandable format (0s and 1s), and runs it on the machine's OS (Windows, Mac, Linux).

## JDK vs JRE vs JVM

**JVM** (Java Virtual Machine): Only handles translation of Bytecode to Machine Code and executes it.

**JRE** (Java Runtime Environment): The environment required to run Java applications.

Formula: **JRE** = **JVM** + Pre-written Libraries (logic for printing, taking inputs, etc.)

**JDK** (Java Development Kit): The complete kit needed to develop and run Java applications.

Formula: **JDK** = **JRE** + Development Tools (Compiler, Debugger, Utilities)

## Hierarchy Structure

**JDK** contains the **JRE**.

**JRE** contains the **JVM** and Libraries.

Therefore: **JDK** > **JRE** > **JVM**.
